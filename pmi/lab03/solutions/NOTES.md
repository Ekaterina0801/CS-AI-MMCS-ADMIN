# Журнал воркшопа по Git

## Сравнение версий

- `git diff HEAD~2 HEAD -- lab03/calc.py` — разница между двумя состояниями файла: строки с `-` были, строки с `+` стали.
- `git show HEAD~1` — один коммит целиком: автор, сообщение и его изменения.
- `git log --oneline --stat` — вся история списком: какой коммит какие файлы задел.

`diff` сравнивает два состояния, `show` показывает один коммит, `log` перечисляет историю. Разные вопросы — разные команды.

## Поиск изменений

- `git log -S"def" --oneline -- lab03/calc.py` — коммиты, где число вхождений строки изменилось: так нашёлся коммит, в котором строка появилась.
- `git blame lab03/calc.py` — для каждой строки коммит и автор, который её добавил.

## Восстановление файла

- `git restore lab03/calc.py` — вернуть файл к последнему коммиту. Несохранённые правки пропадают: Git о них не знал.
- `git restore --source=HEAD~2 lab03/calc.py` — положить в рабочую папку версию из старого коммита. История при этом не меняется, старую версию можно закоммитить как новую.

## Отмена коммита

`git revert HEAD` создал новый коммит, отменяющий ошибочный: ошибка и её исправление остались в истории. `git reset --hard` сдвинул бы ветку назад и выбросил коммиты — в опубликованной истории так делать нельзя, у других коммиты уже скачаны.

## Тег

`git tag -a v1.0 -m "Рабочая версия калькулятора"` — постоянное имя коммита. Тег не двигается, а ветка передвигается при каждом новом коммите. Обычный `git push` теги не отправляет, нужен `git push origin v1.0`.

## Эксперимент в ветке

`git switch -c experiment` — отдельная линия работы: неудачную ветку можно удалить, и `main` останется рабочей. Удачный эксперимент влит обратно командой `git merge --no-ff experiment`.
