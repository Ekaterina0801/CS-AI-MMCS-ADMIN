## Что именно проверяется

| Место | Правильно | Частая ошибка |
|---|---|---|
| разбор CSV | значения строками, пробелы отброшены | приведение к числам — в этой работе не требуется |
| комментарии YAML | всё после # отброшено | комментарий попал в значение |
| списки YAML | «ключ:» без значения открывает список | список остался пустым |
| типы значений | 12 → число, true → логическое, остальное строка | всё осталось строками |
| конфликт ключей | значение записи важнее справочного | справочник затёр данные записи |
| записи без пары | остаются как есть | запись молча потерялась |
| JSON | ключи по алфавиту, отступ 2, кириллица как есть | \u0410\u0437… в файле |

Модуль `yaml` намеренно не нужен: разбирается учебное подмножество формата. В методичке стоит проговорить, что в рабочем коде берут `PyYAML` и именно `safe_load`.

## Вопросы для защиты

Видны только преподавателям. Базовые задайте каждому — два-три на выбор.

### Базовые

**1. Для чего нужен CSV, а для чего JSON?** · _Форматы_

> CSV — однородная таблица: много одинаковых записей, легко читать построчно. JSON хранит вложенные структуры и сохраняет типы.

**2. Почему настройки хранят в YAML, а не в CSV?** · _Форматы_

> Настройки правит человек: в YAML видно ключи, можно писать комментарии и списки. Таблицей это не выразить.

**3. Что делает ваш разбор со строкой после символа #?** · _YAML_

> Отбрасывает: это комментарий. Поэтому значение берётся из части строки до #.

**4. Как в вашем разборе появляется список?** · _YAML_

> Строка «ключ:» без значения открывает список, а следующие строки, начинающиеся с «- », добавляют в него элементы.

**5. Почему 12 из настроек становится числом, а «Отчёт» остаётся строкой?** · _YAML_

> Значение пробуют привести к числу, и если не выходит — оставляют строкой. true и false отдельно переводятся в логический тип.

**6. Ключ есть и в записи, и в справочнике. Чьё значение останется?** · _Объединение_

> Записи: справочник только дополняет. Сначала берутся поля справочника, потом поверх них накладываются поля записи.

**7. Что будет с записью, которой нет в справочнике?** · _Объединение_

> Останется как есть, без дополнительных полей. Пропускать такие записи нельзя: данные бы потерялись.

**8. Зачем в JSON сортировать ключи и ставить отступы?** · _JSON_

> Чтобы файл читался человеком и чтобы одинаковые данные давали одинаковый текст — иначе каждая выгрузка отличалась бы порядком ключей.

### Сложные

**9. Почему в JSON кириллицу не экранируют?** · _JSON_

> ensure_ascii=False оставляет буквы как есть. Иначе «Азов» превратится в \u0410\u0437\u043e\u0432 и файл станет нечитаемым.

**10. Чем настоящий CSV сложнее нашего разбора?** · _Форматы_

> В значениях бывают запятые и переводы строк, их берут в кавычки. Такой файл разбирают модулем csv, а не split.
