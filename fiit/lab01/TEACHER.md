## Разбалловка в сервисе

| Критерий | Баллы | Кто | Ключ в сервисе |
|---|:---:|---|---|

Каждую задачу сервис запускает трижды: пример из условия, ещё один открытый вход и один скрытый.
Три теста задачи дают 1 балл, поэтому частично верное решение автоматически получает часть балла —
это то «0,5 балла за частично выполненную задачу», что предусматривает практикум.

Отчёт проверяется так: таблица должна содержать не меньше 18 заполненных строк, разделы «Автор»,
«Решения», «Проверки», «Объяснения» — присутствовать. Если в отчёте остались заготовки из шаблона
вида `<ваше описание>`, балл за отчёт делится пополам. Качество объяснений автоматика не оценивает —
это видно на защите.

## Как проверять

1. **Очередь проверки** → «Автопроверка прошла, оценка не выставлена» → откройте попытку.
2. Сверху — итог автоматической части. Раскройте группу «Автотесты»: у проваленных тестов виден ввод,
   ожидаемый и полученный вывод. У скрытых — только факт провала, но вам в [TESTS.md](TESTS.md) видно всё.
3. Внизу страницы — **вопросы для защиты**. Задайте два-три, отметьте «ответил / частично / не ответил».
4. Поставьте баллы за два ручных критерия и отметьте «Оценка окончательная».

## Типичные ошибки

| Задача | Что встречается | Как это выглядит в разборе |
|---|---|---|
| **все** | приглашение в `input("Введите число: ")` — текст уходит в вывод | вывод начинается с «Введите…», тесты не проходят |
| **все** | нет форматирования: `print(mean)` | пример из условия проходит, а на `1, 2, 2` выводится `1.6666666666666667` вместо `1.7` |
| 1 | `a + b + c / 3` без скобок | на примере из условия `14.333…` вместо `7.0` |
| 1 | `int(input())` | падает на дробном вводе: `ValueError` |
| 2 | `2 * w + h` | периметр не совпадает; площадь при этом верна — тест частично падает |
| 2 | площадь и периметр одной строкой через `print(s, p)` | вывод в одну строку, тест не проходит |
| 3 | `int` для цены | `ValueError` на `45.50` |
| 3 | `:.1f` вместо `:.2f` | `182.0` вместо `182.00` |
| 4 | `(C + 32) * 9 / 5` | неверно везде, кроме частных совпадений |
| 5 | `a, b = b, a` вместо третьей переменной | **тесты проходят** — см. ниже |
| 5 | `a = b` затем `b = a` | оба значения становятся одинаковыми |
| 6 | `print("Студент:", name, ". Группа:", group)` | лишние пробелы вокруг точки: `Анна . Группа` |

### Обмен через кортеж

Практикум требует обмен **через третью переменную**. Запись `a, b = b, a` даёт тот же вывод, и автотесты
её не отличают. Сервис отмечает такую запись в разделе «Анализ кода» как запрещённую конструкцию, но баллы
за тесты не снимает — вывод ведь верный. Решение за вами: на защите попросите показать значения `a`, `b`
и `temp` по шагам — это и так первый вопрос второго ручного критерия.

## Совпадения работ

Для этой работы одинаковый код у разных студентов — **норма**: правильное решение задачи в три строки
почти единственное. Сервис исключает из сравнения фрагменты, встречающиеся у трети группы, но этот фильтр
включается, когда сдано хотя бы пять работ. Пока работ меньше, пары помечаются «сдано мало работ».

Показательнее совпадение **отчётов**: собственные примеры и объяснения у честно работавших студентов
разные. Если совпали таблицы проверок с одинаковыми «своими» входами — это повод поговорить.

## Вопросы для защиты

Видны только преподавателям. В сервисе — вкладка «Вопросы защиты» у практики и форма проверки попытки.

**1. Чем отличаются значения 4 и "4"? Что даст сложение в каждом случае?** · _Типы_

> 4 — число, "4" — строка. Сложение чисел даёт сумму, сложение строк соединяет текст.

**2. Что возвращает input() и зачем нужен float()?** · _Ввод_

> input() всегда возвращает строку; float() превращает числовую запись в число.

**3. Почему print(8 + 4 / 2) даёт 10.0, а не 6.0?** · _Порядок действий_

> Деление выполняется раньше сложения; скобки меняют порядок вычисления.

**4. Что делает формат :.1f — меняет ли он само значение?** · _Вывод_

> Только отображение: печатает один знак после точки, само значение не меняется.

**5. Покажите значения a, b и temp после каждой инструкции обмена в задаче 5.** · _Обмен значениями_

> temp = a сохраняет исходное a; a = b перезаписывает a; b = temp возвращает старое a.

**6. Почему последовательность a = b, затем b = a не меняет числа местами?** · _Обмен значениями_

> После первой инструкции исходное значение a потеряно, и b получает уже новое a.
