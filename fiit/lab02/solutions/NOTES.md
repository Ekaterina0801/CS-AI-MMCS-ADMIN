# Локальные состояния Git

**Рабочая папка** — файлы, которые я вижу и правлю в редакторе. Сохранение файла меняет только её и Git об этом ещё ничего не решает.

**Индекс** — промежуточная область, куда `git add` переносит выбранные изменения. Индекс отвечает на вопрос «что именно уйдёт в следующий коммит».

**Коммит** — зафиксированное состояние индекса с автором, временем и сообщением. Он неизменен и лежит в локальной истории.

## Git и GitHub

Git — программа, которая ведёт историю на моём компьютере. GitHub — сервис, где эта история публикуется и становится видна другим. Пока не выполнен `git push`, коммит существует только локально: на GitHub его нет.

## Использованные команды

- `git status` — что изменилось в рабочей папке и что подготовлено в индексе.
- `git add <файл>` — перенести изменение в индекс.
- `git diff` — сравнить рабочую папку с индексом.
- `git diff --staged` — сравнить индекс с последним коммитом.
- `git commit -m "..."` — зафиксировать подготовленное изменение.
- `git push origin main` — опубликовать коммиты в своём репозитории на GitHub.
- `git rev-parse HEAD` — полный идентификатор сдаваемого коммита.

## Ветки

Ветка — именованный указатель на коммит. При новом коммите текущая ветка передвигается на него, а `main` остаётся на месте. Слияние `git merge` переносит изменения ветки в `main`; с `--no-ff` в истории появляется коммит слияния с двумя родителями.
