# Как завести практику

## 1. Курс

Админка → **Курсы**. Код курса, направление и **подкаталог в репозитории студента**
(`pmi` или `fiit`). Путь к работе складывается как `подкаталог / каталог практики`.

Если практики уже описаны в `courses.json` репозитория, воспользуйтесь импортом: он создаст
курсы и практики с названиями, статусами и списками обязательных файлов.

## 2. Практика

Админка → **Практики** → «Новая практика».

| Поле | Что задаёт |
|---|---|
| Тип проверки | какие проверки запускаются |
| Статус | `черновик` не выдаётся студентам, сдать его нельзя |
| Обязательные файлы | без них проверка останавливается на ошибке структуры |
| Максимум баллов | шкала практики; сумма тестов и критериев масштабируется к ней |
| Срок и штраф за день | штраф считается от даты коммита, а не от даты отправки |
| Лимит попыток | `0` — без ограничения |
| Настройки проверки (JSON) | параметры конкретного типа |

Полезные ключи JSON:

```json
{
  "solution_file": "solution.py",
  "clean_function": "clean",
  "answers_function": "answers",
  "key_column": "order_id",
  "tolerance": 0.01,
  "report_sections": ["Данные", "Очистка", "Анализ", "Графики", "Выводы"],
  "report_min_words": 150
}
```

## 3. Тесты

Вкладка **Тесты**. Каждый тест — название, баллы, видимость и подсказка, которая
показывается студенту при провале. Виды тестов подобраны под типы практик:

* **Ввод/вывод** — для задач на Python: входные данные и ожидаемый вывод, режим сравнения
  (по строкам, посимвольно, численно с допуском, по подстроке, регулярным выражением).
* **Вызов функции** — имя функции, аргументы JSON-массивом, ожидаемое значение.
* **Код теста** — обычный файл `pytest`; кладётся рядом с решением, балл делится между
  тестовыми функциями файла.
* **Ответ на вопрос** — ключ из `ANSWERS` и ожидаемое значение с допуском.
* **Ожидаемый график** — тип, ключевые слова заголовка, требования к подписям, число серий
  и точек, эталонные значения для сверки данных за графиком.
* **Сверка датасета** — сравнение результата очистки с эталоном.

Видимость: *открытый* показывает вход и результат, *скрытый* — только факт прохождения,
*секретный* вообще не попадает в отчёт студента.

## 4. Критерии и баллы

Вкладка **Критерии**. Два вида:

* **автоматические** — выбираются из каталога ключей и считаются сервисом. Тонкая настройка
  через JSON: пороги, списки требуемых операций, минимальные доли. Например,
  `data.no_row_loss` с `{"min_rows_kept_share": 0.9}` требует сохранить 90% наблюдений;
  `charts.count` с `{"min_charts": 3}` — построить три графика.
* **ручные** — выставляются преподавателем на странице попытки, с комментарием по каждому
  критерию и общим комментарием студенту.

Пока ручные баллы не выставлены, итог считается только по автоматической части.

## 5. Датасеты

Вкладка **Датасеты**:

* **train** — исходные данные, которые получают студенты. Сервис кладёт этот файл рядом с
  решением при проверке, поэтому студент читает его по имени.
* **reference** — эталонный результат очистки. С ним сверяется работа студента.

Эталон надёжнее всего получать той же функцией очистки, которую вы считаете правильной:
тогда допуски и порядок колонок гарантированно согласованы.

## 6. Проверка работ

* **Очередь проверки** — что ждёт ручной оценки и что сейчас считается.
* Страница попытки — разбор по категориям, построенные графики, служебный журнал и форма
  выставления ручных баллов.
* **Журнал оценок** — сводка по курсу, лучший результат каждого студента, выгрузка в CSV.

Кнопка «Перепроверить этот коммит» создаёт новую попытку по тем же ссылке и коммиту —
удобно после исправления тестов или критериев.

## Отладка задания до выдачи

Проверьте настройки на локальном каталоге, не поднимая репозиторий:

```bash
./.venv/bin/python tests/run_checker.py <id практики> <каталог с решением> <ник студента>
```

Прогоните эталонное решение (должно быть 100% автоматической части) и заведомо небрежное
(должно давать понятные сообщения). Примеры обоих — в `tests/fixtures/`.
