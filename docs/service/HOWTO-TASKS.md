# Как добавить лабораторную: тесты, проверки и типы работ

Всё настраивается в админке — файлы на сервере править не нужно.

## Коротко: пять шагов

1. **Создать практику** — тип, способ сдачи, условие. Статус оставить «Черновик».
2. **Настроить проверки** — тесты и датасеты; набор зависит от типа практики.
3. **Задать критерии и разбалловку** — что считает сервис, что оценивает преподаватель.
4. **Добавить вопросы для защиты и материалы.**
5. **Проверить своим эталонным решением** и только потом выдать студентам.

> Быстрее всего начинать с копии похожей практики: **Практики → кнопка «Копия»**.
> Копируются условие, настройки, тесты, критерии, датасеты и вопросы защиты; копия создаётся
> черновиком. Материалы не копируются — они привязаны к конкретной лекции.

---

## Шаг 1. Создать практику

**Практики → Новая практика**, вкладка «Основное».

| Поле | Что писать |
|---|---|
| Курс | направление: ПМИ или ФИИТ |
| Код практики | `lab03` — так же называется папка работы у студента |
| Название | видно студенту в списке практик |
| **Тип проверки** | какие проверки запустятся — см. таблицу ниже |
| **Как студенты сдают** | файлами, ссылкой на репозиторий или любым способом |
| Статус | «Черновик» — студенты практику не видят; «Выдана студентам» — когда всё проверено |
| Обязательные файлы | по одному в строке: `task01.py`, `task02.py` |
| Максимум баллов | шкала практики, например 10 |
| Порог зачёта | процент от максимума |
| Срок и штраф за день | для репозитория штраф считается от даты коммита, для файлов — от даты отправки |
| Лимит попыток | 0 — без ограничения; засчитывается лучшая попытка |

**Условие** пишется там же, в редакторе. Кнопки над полем вставляют заголовок, код, список
и таблицу; «Предпросмотр» показывает текст ровно так, как его увидит студент.

### Какой тип выбрать

| Тип | Для каких работ | Чем проверяется |
|---|---|---|
| **Задача на Python** | программы с `input()`, функции | автотесты: ввод/вывод, вызов функции, код теста |
| **Анализ данных** | очистка таблиц, ответы на вопросы, графики | сверка с эталоном, ответы, разбор графиков |
| **Jupyter-ноутбук** | связный анализ в `.ipynb` | выполнен ли ноутбук, нет ли ошибок, есть ли пояснения |
| **Дашборд Yandex DataLens** | работа вне репозитория | ссылка, выгрузка воркбука, скриншоты |
| **Git и защита** | работа с Git, без тестов кода | история коммитов, пояснения в заметках, защита |

### Как студенты сдают

| Способ | Когда выбирать |
|---|---|
| **Файлами или ZIP** | первые работы, до знакомства с Git |
| **Ссылкой на свой репозиторий** | всё, где оценивается история коммитов |
| **Любым способом на выбор** | когда это не принципиально |

ZIP можно прислать как угодно упакованным — сервис сам найдёт файлы работы внутри.
Если у практики есть критерии по истории коммитов, а сдаётся она файлами, админка
предупредит: истории у такой работы нет.

## Шаг 2. Настроить проверки

Вкладка **Тесты → Добавить тест**. У каждого теста есть:

* **баллы**;
* **видимость**: *открытый* — студент видит вход, ожидаемый и полученный результат;
  *скрытый* — только «пройден/не пройден»; *секретный* — тест не попадает в разбор, который видит студент;
* **подсказка** — показывается студенту, если тест не пройден.

Правило, которое хорошо работает: примеры из условия — открытыми, пограничные случаи — скрытыми.

Дальше — по типам.

### Задача на Python

**Тест «Ввод/вывод»** — для программ, которые читают `input()` и печатают ответ.

| Поле | Пример |
|---|---|
| Файл решения | `task01.py` |
| Входные данные | каждое значение с новой строки: `4`, `7`, `10` |
| Ожидаемый вывод | `7.0` |
| Точность | «как задано в практике» — или своя для этого теста |
| Числовой допуск | `1e-06` — насколько могут расходиться числа |

**Оформление вывода студент выбирает сам** — f-строки, подписи, подсказки ввода допустимы
всегда. Сервис проверяет значения, а не то, как они напечатаны:

| Студент вывел | Образец | Результат |
|---|---|---|
| `7.0`, `7,0` | `7.0` | засчитано |
| `Среднее: 7.0` | `7.0` | засчитано — подписи не мешают |
| `input("Введите число: ")` в программе | `7.0` | засчитано — подсказка ввода не попадает в вывод |
| `Студент: Анна . Группа: ПМИ-101 .` | `Студент: Анна. Группа: ПМИ-101.` | засчитано — лишние пробелы не важны |
| `7` или `7.00` | `7.0` | **не засчитано — другая точность** |
| `1.6666666666666667` | `1.7` | не засчитано — значение не округлено |
| `12` и `7` | `7` и `12` | не засчитано — порядок важен |
| `a, b, c = map(float, input().split())` | ввод `4`, `7`, `10` построчно | засчитано — тест повторяется с `4 7 10` одной строкой |

**Ввод** студент тоже выбирает сам: каждое значение с новой строки или все одной строкой через пробел. Тест подаёт входные данные построчно, а если программа так не справилась — повторяет тот же ввод одной строкой. Входы, в которых есть пробелы внутри значения («Мария Ивановна»), одной строкой не повторяются.

Числа берутся из конца вывода — столько, сколько их в образце, — и сравниваются по значению.
Текст сравнивается без учёта лишних пробелов; ожидаемая строка может стоять внутри вывода.
В образце достаточно указать сами значения.

**Точность — часть ответа.** Сколько знаков после точки требовать, выбирается в двух местах:

| Где | Поле | Значения |
|---|---|---|
| Практика, вкладка «Основное» | **Точность вывода в тестах** | «как в ожидаемом выводе теста» (по умолчанию), «не проверять», «ровно N знаков» |
| Отдельный тест | **Точность (знаков после точки)** | «как задано в практике» (по умолчанию) или своё значение |

При значении «как в ожидаемом выводе» образец задаёт требование: для `182.00` нужны ровно два знака,
для `7` — целое число без дробной части. Если в задаче формат не важен, поставьте «не проверять».

Если практика состоит из нескольких программ, у каждого теста свой
файл решения. Чтобы несделанная задача не обнуляла остальные, добавьте в настройки практики
`"block_on_missing_files": false`.

**Тест «Вызов функции»** — когда студент пишет функции, а не программу целиком.

| Поле | Пример |
|---|---|
| Имя функции | `square` — без скобок |
| Аргументы вызова | `[7]` — один аргумент, `[3, 4]` — два, `[[1, 2, 3]]` — один аргумент-список |
| Что функция должна вернуть | `49`, `[1, 2, 3]`, `true`, `{"а": 1}`; текст можно без кавычек: `да` |

Одиночный аргумент можно записать и без скобок — `7` сервис сам превратит в `[7]`. Но если
функция принимает **список**, скобки нужны двойные: `[[1, 2, 3]]`, иначе `[1, 2, 3]`
будет прочитан как три отдельных аргумента.

Числа сравниваются с допуском, строки — без учёта регистра и пробелов по краям.
Если поле заполнено неверно, тест не сохранится, и сервис скажет, что именно поправить.

**Тест «Код теста»** — обычный `pytest`, если проверка не укладывается в два предыдущих вида.
Балл делится поровну между тестовыми функциями файла.

```python
import subprocess, sys

def test_output_format():
    run = subprocess.run([sys.executable, "task01.py"], input="4\n7\n10\n",
                         text=True, capture_output=True, timeout=5)
    assert run.stdout.strip() == "7.0"
```

**Настройки практики** (вкладка «Основное», поле JSON):

```json
{
  "entry_file": "solution.py",
  "required_functions": ["divisors", "is_prime"],
  "check_docstrings": true
}
```

Поле «Запрещённые конструкции» принимает регулярные выражения — например, чтобы запретить
готовые библиотеки в задаче про базовый Python. После ` ## ` можно написать пояснение, которое
студент увидит в разборе:

```
\bimport\s+numpy ## в этой задаче без NumPy
@task07.py \bstr\s*\( ## задача 7: число нельзя переводить в строку
```

Строка, начинающаяся с `@имя_файла`, действует только на этот файл: в примере `str()` запрещён
в `task07.py`, а в остальных задачах разрешён. Без `@` запрет проверяется во всех файлах работы.

Нарушение отмечается в разделе «Анализ кода», но баллы за тесты не снимает: вывод при этом
может быть верным. Решение — на защите или отдельным ручным критерием.

### Анализ данных

Здесь порядок другой: **сначала датасеты, потом тесты**.

**Вкладка «Датасеты».**

| Роль | Что загружать |
|---|---|
| **train** | исходная выгрузка, которую получают студенты; сервис кладёт её рядом с решением |
| **reference** | эталон после правильной очистки — с ним сверяется работа |
| **extra** | дополнительная таблица, например справочник для объединения |

Укажите **ключевую колонку** — по ней сопоставляются строки при сверке. Эталон надёжнее всего
получить той же функцией очистки, которую вы считаете правильной: тогда допуски и порядок
колонок гарантированно совпадут.

**Настройки практики:**

```json
{
  "solution_file": "solution.py",
  "clean_function": "clean",
  "answers_function": "answers",
  "key_column": "student_id",
  "tolerance": 0.011
}
```

Договор со студентом: функция `clean(df)` возвращает очищенную таблицу, словарь `ANSWERS`
содержит ответы, графики строятся как обычно — сервис перехватывает их при `plt.show()`
и `savefig()`. Всё построенное студентом сохраняется картинками на странице попытки.

**Тесты:**

| Тест | Что задаёте |
|---|---|
| **Сверка датасета с эталоном** | только баллы; сравниваются колонки, типы, число строк и значения ячеек |
| **Ответ на вопрос** | ключ ответа в `ANSWERS` (`q_mean_score`), ожидаемое значение, числовой допуск |
| **Ожидаемый график** | тип, ключевые слова заголовка, требования к подписям, эталонные значения |

У ответов **обязательно** ставьте допуск для дробных чисел, например `0.01`. У графика ключевые
слова ищутся в заголовке — поэтому в условии попросите осмысленный заголовок, а не «График 1».
Эталонные значения графика — JSON-массив высот столбцов или точек линии: так проверяется,
что график построен по правильно посчитанным данным.

Ответы, записанные в `ANSWERS` готовыми числами, а не вычисленные, сервис распознаёт
и не засчитывает.

### Jupyter-ноутбук

Тестов здесь нет — проверяется сам ноутбук. Достаточно настроек и критериев.

```json
{
  "notebook_file": "analysis.ipynb",
  "min_markdown_cells": 6,
  "execute_notebook": false
}
```

| Критерий | Что проверяет |
|---|---|
| `notebook.executed` | все ячейки выполнены, номера идут по порядку |
| `notebook.no_errors` | в выводах нет ошибок |
| `notebook.narrative` | достаточно текстовых пояснений: `{"min_markdown_cells": 6}` |

Если поставить `"execute_notebook": true`, код ноутбука дополнительно прогоняется тем же движком,
что и анализ данных, — тогда работают и проверки графиков. Требование студентам:
перед сдачей выполнить **Kernel → Restart & Run All**.

### Дашборд Yandex DataLens

Дашборд живёт вне репозитория, поэтому студент сдаёт три вещи: публичную ссылку одной строкой в `LINK.txt`,
выгрузку воркбука `datalens_export.json` и скриншот.

```json
{
  "check_link_online": true,
  "require_export": true,
  "min_screenshots": 1
}
```

| Критерий | Настройка |
|---|---|
| `datalens.link` | ссылка найдена и открывается без входа в аккаунт |
| `datalens.charts` | `{"min_charts": 4, "required_types": ["column", "line", "pie"]}` |
| `datalens.dataset` | `{"required_fields": ["revenue"], "require_calculated": true}` |
| `datalens.filters` | `{"min_filters": 2}` |

Оформление и смысл дашборда автоматика не оценит — для этого заведите ручной критерий.

### Git и защита

Способ сдачи — **ссылкой на свой репозиторий**: сервис скачивает историю и отличает коммиты
студента от унаследованных при форке.

| Критерий | Настройка | Что проверяет |
|---|---|---|
| `git.own_commits` | `{"min_commits": 3}` | число собственных коммитов |
| `git.commit_messages` | `{"min_share": 0.8}` | доля осмысленных сообщений; «update», «фикс», «1» не считаются |
| `git.commit_granularity` | `{"max_bulk": 0}` | нет коммита, в котором почти вся работа |
| `git.branching` | `{"min_merges": 1}` | было слияние ветки |
| `git.revert` | `{"min_reverts": 1}` | изменение отменено через `git revert` |
| `git.work_spread` | `{"min_days": 2}` | работа не сделана за один заход |
| `git.published` | `{"min_commits": 3}` | изменения опубликованы в fork |
| `git.no_web_commits` | `{"max_share": 0.3}` | правки сделаны не через кнопку «Edit» на сайте |

Содержание пояснений проверяет критерий **`text.keywords`**: он ищет в файле нужные понятия.
Группа синонимов засчитывается, если найден любой из них.

```json
{"file": "NOTES.md", "groups": [["рабоч"], ["индекс", "staging"], ["коммит"], ["github"]]}
```

## Шаг 3. Критерии и разбалловка

**Вкладка «Критерии и баллы».** Два вида:

* **Автоматический** — выберите ключ из списка, под ним появится подсказка и настройки
  по умолчанию. Около сорока ключей по группам: Структура, Git, Данные, Анализ, Графики,
  Честность, Текст, Ноутбук, DataLens.
* **Ручной** — ставит преподаватель на странице попытки. Сюда идёт защита.

Критерии, полезные для любого типа:

| Критерий | Настройка |
|---|---|
| `structure.required` | все обязательные файлы на месте |
| `text.keywords` | в текстовом файле раскрыты нужные понятия |

**Вкладка «Разбалловка»** показывает всю картину сразу: цену каждого теста, вес каждого
критерия, сумму и максимум практики. Веса можно менять прямо там. Если сумма рубрики
не совпадает с максимумом, сервис пересчитает баллы пропорционально и предупредит — но оценки
читать проще, когда суммы равны.

## Шаг 4. Вопросы для защиты и материалы

**Вкладка «Вопросы защиты».** Видна только преподавателям. У вопроса есть тема, уровень
и поле «что должно прозвучать в ответе» — подсказка вам на защите. В форме проверки попытки
вопросы выводятся списком: отмечаете «ответил / частично / не ответил» и тут же ставите балл.

**Вкладка «Материалы».** Презентации, практикумы, методички — файлом или ссылкой.
Теорию и шпаргалки удобнее писать прямо в редакторе: студент откроет их страницей, без
скачивания. У каждого материала выбирается, кому он виден — только преподавателям или всем.

## Шаг 5. Проверить перед выдачей

**Не выдавайте практику, не прогнав через неё правильное решение.**

1. Пока практика — черновик, откройте **«Проверить решение»** в меню преподавателя.
   Черновики там видны с пометкой «черновик, студентам не видна».
2. Отправьте своё эталонное решение тем же способом, каким будут сдавать студенты.
3. Эталон должен набрать **100% автоматической части**. Если не набирает — условие, тесты
   или датасет противоречат друг другу, и студент столкнётся с тем же самым.
4. Отправьте заведомо небрежное решение и прочитайте разбор: понятны ли сообщения. Именно их
   студент увидит вместо вашего объяснения.
5. Переключите статус на **«Выдана студентам»**.

Ваши попытки не попадают в журнал оценок и в поиск совпадений: эталон преподавателя похож
на каждое правильное решение, и это не списывание.

## Частые ошибки при настройке

| Симптом | Причина и что сделать |
|---|---|
| Эталон не набирает 100% | критерий требует того, чего нет в условии; сверьте рубрику с текстом задачи |
| «Функция не найдена» | не совпадает имя файла: поле «Файл решения» и `entry_file` |
| Ответ верный, а тест не проходит | нулевой допуск; для дробных поставьте `0.01` |
| «Очищенный датасет не найден» | студент не определил `clean()` или в настройках другое имя функции |
| График не найден | ключевые слова не встречаются в заголовке графика студента |
| Git-критерии всегда дают ноль | практика сдаётся файлами — переключите на «ссылкой на репозиторий» |
| Студент не видит практику | статус «Черновик» |
| Нельзя сдать: «Эта практика сдаётся файлами» | студент прислал ссылку; способ сдачи задаётся у практики |
