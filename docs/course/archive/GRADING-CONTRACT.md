# Контракт для будущего сервиса проверки · версия 1

Это спецификация интеграции. В этом репозитории нет сервера, загрузчика GitHub и изолированного исполнителя. tools/check.py предназначен только для локальной самопроверки собственных работ.

## Каталог

Сервис читает course.json из доверенного репозитория преподавателя на фиксированном коммите. Студенческая копия course.json, tests и tools не является источником правил проверки. status=draft запрещает сдачу; grading.mode=manual требует ручной проверки. grading.mode=not_configured не означает нулевое количество тестов.

## Входные данные

Аутентифицированный студент, URL его GitHub-репозитория, course_id, assignment_id и выбранный ref. Сервер проверяет принадлежность/доступ, разрешает ref в полный commit SHA и сохраняет его до постановки в очередь. Принимаются только допустимые GitHub URL; произвольные адреса и пользовательские команды не исполняются.

## Структура

repository_subdirectory задаёт папку направления относительно корня репозитория. path в записи практики задаётся относительно неё. Например, pmi + lab01 → pmi/lab01. Локальный check.py уже определяет свою папку направления по расположению файла.

Путь практики и required_files берутся из доверенного каталога. Пути относительны папке практики; не допускаются выход за каталог и ссылки на внешние файлы. При несовпадении структуры возвращается structure_error с перечнем проблем. Не нужно искать похожие файлы по всему репозиторию или подменять недостающий файл чужой практикой.

## Выполнение

Изолированный одноразовый исполнитель получает разрешённые файлы решения и доверенные тесты. Зависимости определяет преподаватель. Не запускать произвольные workflow, install-скрипты и тесты из студенческого fork. Ограничить время, память, число процессов, объём вывода и сеть. Не передавать в среду выполнения токены GitHub и доступ к базе оценок. Локальный timeout в check.py НЕ заменяет такую изоляцию.

## Результат

Хранить attempt_id, student_id, assignment_id, student_commit_sha, teacher_commit_sha, assignment_version, started_at, finished_at, status, structure, tests и manual_score. SHA и время создаёт сервер; примеры значений не следует принимать на доверии от клиента.

В tests хранить total, passed, failed, errors, skipped и список разрешённых к показу деталей. Пропущенные тесты не считать пройденными. Если запуска не было (draft, manual, ошибка инфраструктуры), tests=null, а не 0 из 0. Итоговый процент определяется только после завершённой проверки; ручные баллы отдельны.

Статусы: queued, running, completed, structure_error, infrastructure_error, not_published, manual_review. Для completed отдельно указывается, прошли ли все тесты. При тайм-ауте студенческой программы фиксируется ошибка теста; при сбое исполнителя — инфраструктурная ошибка без штрафа студенту.

## Первая интеграция

lab01 — открытые тесты Python и отчёт. lab02 — ручная проверка Git; будущий анализатор должен отличать собственные коммиты студента от унаследованной истории. lab03–lab14 не активировать до публикации условий и тестов.
